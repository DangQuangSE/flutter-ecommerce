# Phase 4: Product — SizeGroup FK + DTO

## Requirements
Wire the `SizeGroup` entity into `Product` as a nullable many-to-one relationship, propagate `sizeGroupId` through the request and response DTOs, and update `ProductService` to look up and assign the size group when provided. Existing products remain unaffected (FK is nullable).

## Steps

1. Add a `@ManyToOne(fetch = FetchType.LAZY)` field `private SizeGroup sizeGroup` to `Product.java` with `@JoinColumn(name = "size_group_id")` (no `nullable = false` — the column must remain nullable). Import `com.sport_pro_be.modules.size.domain.SizeGroup`.

2. Add `private Long sizeGroupId` (no validation annotation — it is optional) to both `ProductCreateRequest.java` and `ProductUpdateRequest.java`.

3. Add `private Long sizeGroupId` to `ProductDetailResponse.java` alongside the other scalar fields.

4. Inject `SizeGroupRepository` into `ProductService` via constructor injection (`final` field + `@RequiredArgsConstructor`). Add the import.

5. In `ProductService.createProduct()`, after resolving `category` and `brand`, add a nullable lookup: if `request.getSizeGroupId() != null`, fetch `SizeGroup` from `SizeGroupRepository` (throw `ResourceNotFoundException` with message `"Size group not found"` if absent), then add `.sizeGroup(sizeGroup)` to the `Product.builder()` chain.

6. In `ProductService.updateProduct()`, after resolving `category` and `brand`, add the same nullable lookup and call `product.setSizeGroup(sizeGroup)` — or `product.setSizeGroup(null)` if `sizeGroupId` is not provided in the update request (allowing callers to clear the association).

7. In `ProductService.mapToDetailResponse()`, add `.sizeGroupId(product.getSizeGroup() != null ? product.getSizeGroup().getId() : null)` to the `ProductDetailResponse.builder()` chain.

## Success Criteria
- `POST /api/admin/products` with `"sizeGroupId": 1` saves the association; `GET /api/admin/products/{id}` returns `"sizeGroupId": 1`
- `POST /api/admin/products` without `sizeGroupId` field succeeds; response contains `"sizeGroupId": null`
- `PUT /api/admin/products/{id}` with `"sizeGroupId": null` clears the association
- `POST /api/admin/products` with a non-existent `sizeGroupId` returns `404`
- Application starts; `products` table gains a nullable `size_group_id` column

## Risks
- `Product` uses `@Builder` — the new `sizeGroup` field does NOT need `@Builder.Default` (null is the correct default for a nullable FK). Confirm that the `@AllArgsConstructor` generated by `@Builder` does not break any existing test that directly instantiates `Product`.
- `mapToDetailResponse` calls `product.getSizeGroup()` which triggers a LAZY load — this is safe because `ProductService` methods are `@Transactional`, keeping the session open.

## Dependencies
- Phase 3 must be complete. `SizeGroup.java` and `SizeGroupRepository.java` must exist before `Product.java` can import them.
